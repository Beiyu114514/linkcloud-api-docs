这一节按**症状**组织。具体错误原文的含义见[错误码](/errors)。

## 初步确认

1. **取得完整报错**。客户端界面上的提示通常经过简化，需要 HTTP 状态码和响应里的 `message` 原文。

2. **查看[使用记录](https://api.linkcloud.sh/usage)**。请求是否到达 LinkCloud、用了哪个模型和 Key、返回什么状态码，都能在这里核对。记录里没有该请求时，先确认时间范围、账号和 Key，再检查客户端是否真的发出了请求。

3. **确认网络可达**：

   ```bash
   curl https://api.linkcloud.sh/health
   ```

   返回 `{"status":"ok"}` 只说明当前网络能访问网关，不能排除具体模型或上游故障。整体可用性看[服务状态页](https://codex-status.linkcloud.sh)。

## 单独测试 Key 和端点

先在终端设置密钥，不要把密钥写进共享脚本或截图：

```bash
export KEY="YOUR_LINKCLOUD_API_KEY"
```

### 查询模型列表

```bash
curl -sS -i https://api.linkcloud.sh/v1/models -H "Authorization: Bearer $KEY"
```

这个请求不产生推理费用。

| 返回 | 能确认什么 |
| --- | --- |
| 模型列表 | 认证通过，继续测推理接口 |
| `401` | 认证未通过，见下方 401 一节 |
| `403` | 请求被拒绝，见下方 403 一节 |

模型列表通过，不代表推理接口、特定模型或流式响应可用。

### 发送最小推理请求

**以下请求会产生费用。** 把 `MODEL_ID` 换成分组内的完整模型 ID，按客户端实际使用的协议选一条。

```bash Chat Completions
curl -sS -i https://api.linkcloud.sh/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"MODEL_ID","messages":[{"role":"user","content":"只回复 OK"}],"stream":false}'
```

```bash Responses
curl -sS -i https://api.linkcloud.sh/v1/responses \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"MODEL_ID","input":"只回复 OK","stream":false}'
```

```bash Anthropic Messages
curl -sS -i https://api.linkcloud.sh/v1/messages \
  -H "x-api-key: $KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"model":"MODEL_ID","max_tokens":128,"messages":[{"role":"user","content":"只回复 OK"}],"stream":false}'
```

返回 2xx 且响应里带模型生成的文本，说明这组 Key、模型、协议的非流式调用成功。若 curl 成功而客户端仍然失败，对比端点、模型 ID、密钥、代理和请求参数。

## 连不上，或配置后没反应

按顺序检查：

1. 地址必须是 `https://`，不是 `http://`。
2. 地址格式与客户端要求的协议一致：

   | 客户端配置项 | 填写 |
   | --- | --- |
   | `OPENAI_BASE_URL` 或「OpenAI 兼容」 | `https://api.linkcloud.sh/v1` |
   | `ANTHROPIC_BASE_URL` | `https://api.linkcloud.sh` |

3. 不要在地址后自行拼接 `/chat/completions` 或 `/v1/messages`，客户端会自动补全。
4. 本地代理、防火墙或证书拦截。部分网络环境需要代理，或应改用中国优化线路，见 [API 端点](/endpoints#备用线路)。
5. 默认线路不稳定时，换成 `https://api-us-co.linkcloud.sh`（Anthropic）或 `https://api-us-co.linkcloud.sh/v1`（OpenAI）。

## 401 认证失败

| 情况 | 处理 |
| --- | --- |
| 请求没带 Key | 检查客户端是否读取到了配置。返回信息会提示需要请求头 |
| Key 不存在 | 检查是否有空格、换行或引号混入 |
| Key 被禁用 | 在 [API 密钥页面](https://api.linkcloud.sh/keys) 查看状态 |
| Key 已过期 | 过期 Key 不可恢复，需要新建 |
| 账号被停用 | 联系支持 |

修改 Key 后仍然返回 401，通常是客户端还在使用旧配置。**完全退出客户端后重新启动**，仅重载窗口通常不够。

## 403 被拒绝

| 情况 | 处理 |
| --- | --- |
| 余额不足 | 充值，见[余额与计费](/account/billing#充值) |
| 分组不可用 | 分组被删除或停用，换分组重建 Key |
| 模型不在分组内 | 报错通常会带出可用模型，从中选择或更换分组 |
| 分组不支持该协议 | 例如只开放 Anthropic 格式的分组，用 `/v1/chat/completions` 就会被拒绝 |
| 客户端限制 | 例如 `claude_max` 只接受 Claude Code |
| IP 不在白名单 | 在 Key 的 IP 限制里补充当前出口 IP |
| 命中风控 | 调整输入内容后重试 |

## 429 额度或限流

先区分是**额度用尽**还是**频率超限**：

| 类型 | 典型原因 | 处理 |
| --- | --- | --- |
| 额度用尽 | Key 的总限额、5 小时 / 日 / 7 天限额，或团队成员的日 / 周 / 月限额 | 等待窗口重置或调整限额；余额不足则充值 |
| 频率超限 | Key 的 RPM 或并发限制、用户级限流、上游限流 | 降低请求频率或并发数，稍后重试 |

响应里带 `Retry-After` 时按其指示等待，否则采用指数退避。**失败重试同样可能产生费用，不要循环重试。**

## 400 请求格式错误

| 情况 | 处理 |
| --- | --- |
| 未传模型 | 检查客户端是否已选择模型 |
| 请求体不是合法 JSON | 检查自定义脚本的序列化逻辑 |
| 复合 Key 的模型没带前缀 | 改成 `前缀/模型ID`，见[创建 API Key](/create-api-key#模型控制) |
| Key 写在 URL 查询参数里 | 改用请求头 |

## 5xx 服务端错误

`502` 和 `503` 通常是临时故障，与客户端配置无关：

- 等待 1–2 分钟后重试，或更换模型 / 分组。
- `529` 一类过载错误说明上游繁忙，换模型更快恢复。
- 持续不恢复时，按下方模板反馈。

## 怎么反馈

自查后仍未解决时，按模板提供信息。分享前移除 API Key、`Authorization` 请求头及私人对话内容，截图也要脱敏。

```text
模型 ID：
分组：
客户端：
API 地址：
系统：
故障：
预期：
复现步骤：
对比：
```

| 字段 | 填什么 |
| --- | --- |
| 模型 ID | 从模型广场复制的完整 ID，不要简写 |
| 分组 | Key 绑定的分组名 |
| 客户端 | 名称与版本，例如 `Claude Code 2.x` |
| API 地址 | 实际填写的地址 |
| 系统 | Windows / macOS / Linux |
| 故障 | 具体现象，附 HTTP 状态码和 `message` 原文 |
| 预期 | 认为正确的表现 |
| 复现步骤 | 触发问题的最小操作 |
| 对比 | 何种情况正常、何种情况异常 |

模型 ID、分组、客户端、API 地址和完整报错缺一不可。同一条报错在不同组合下原因可能完全不同。
