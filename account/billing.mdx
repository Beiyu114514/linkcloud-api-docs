LinkCloud 采用预付费余额制：先充值，再按实际调用扣费。所有分组共用同一个余额，单位为 USD（`$`）。

## 计费规则

单次请求的费用由三部分组成：

```
实际扣费 = 模型单价 × 分组倍率 × 用量
```

| 因素 | 说明 |
| --- | --- |
| 模型单价 | 由模型本身的输入、输出、缓存价格决定，见模型广场的完整价目 |
| 分组倍率 | Key 绑定的分组带来的系数，见[核心概念](/concepts#分组) |
| 用量 | 实际消耗的 token 数或图片张数 |

此外还有两个可能叠加的因素：

- **Fast 模式**：走高优先级通道时单价高于标准通道。Key 上可以设置为跟随请求、强制开启或强制关闭。
- **高峰 / 专属倍率**：部分分组配置了分时倍率，或对特定账户配置了专属倍率。

<Info>
控制台显示的价格已包含分组倍率。使用记录里会同时给出**标准价**和**实际扣费**，两者差额来自倍率和专属折扣，不是重复计费。
</Info>

## 扣费顺序

1. 优先使用当前可用的订阅权益（如果账户持有）。
2. 没有可用订阅时，从账户余额扣减。

每笔扣费都会写入使用记录，可在[使用记录](https://api.linkcloud.sh/usage)逐条核对。

## 充值

**入口：[api.linkcloud.sh/purchase](https://api.linkcloud.sh/purchase)**

在充值页选择金额并完成支付，余额实时到账。可选支付渠道以页面显示为准。

<Note>
充值页同时提供优惠码输入框，符合条件的订单可以使用优惠码抵扣。优惠码与兑换码是两种不同的东西：优惠码用于购买时抵扣，兑换码用于直接兑换余额或权益。
</Note>

| 方式 | 入口 | 说明 |

| 兑换码 | [兑换页面](https://api.linkcloud.sh/redeem) | 可兑换余额、并发数或订阅权益，见[兑换码](/account/redeem) |

## 低余额提醒

开启后，余额低于阈值时会收到提醒邮件，阈值默认 `$5`。邮件中包含充值入口，方便直接续费。

## 限额与余额的关系

余额是账户层面的总量上限，Key 上还可以设置独立限额：

| 层级 | 限制内容 |
| --- | --- |
| 账户 | 余额是否足够支付本次请求 |
| Key | 总限额、5 小时 / 日 / 7 天限额、并发、RPM |
| 团队 | 成员的日 / 周 / 月限额（团队账户） |

任一层级不足都会导致请求被拒绝。区分方法见[错误码](/errors)。

## 账单核对

怀疑扣费异常时，按下面顺序核对：

1. 打开[使用记录](https://api.linkcloud.sh/usage)，按时间范围筛选。
2. 展开单条记录，查看**费用构成**：输入、输出、缓存读、缓存写的 token 数与单价。
3. 对比**标准价**与**实际扣费**，确认差额是否来自分组倍率。
4. 确认请求的模型 ID 与你预期一致。部分客户端会自动选择模型，可能与你的设置不同。

<Warning>
服务端时区为 `Asia/Shanghai`（UTC+08:00）。按日统计和日限额的重置时间以该时区为准，跨时区核对账单时注意换算。
</Warning>
