排查之前先区分两类错误，处理方式完全不同。

## 两类错误

| 类型 | 特征 | 处理方向 |
| --- | --- | --- |
| 网关返回 | JSON 结构统一，通常包含 `code` 和 `message` | 按状态码和 `message` 处理，见下方各节 |
| 上游透传 | 结构随厂商不同（OpenAI / Anthropic / Google 各自的格式） | 内容来自模型服务商，按厂商文档理解 |

部分上游错误会原样返回，因此同一条报错在不同分组下原因可能不同。反馈时请附上状态码和 `message` 原文。

## 状态码总览

| 状态码 | 含义 | 常见原因 |
| --- | --- | --- |
| `400` | 请求格式错误 | 缺模型、JSON 非法、复合 Key 未带前缀、Key 写在 URL 里 |
| `401` | 认证失败 | 未带 Key、Key 无效、被禁用、已过期、账号停用 |
| `403` | 请求被拒绝 | 余额不足、分组不可用、模型不在分组、协议不支持、客户端限制、IP 限制、风控 |
| `404` | 路径不存在 | 地址多拼了路径，或用了不存在的端点 |
| `429` | 额度用尽或频率超限 | Key 限额、团队限额、RPM、并发、上游限流 |
| `502` / `503` | 上游故障 | 服务过载、无可用上游、临时网络问题 |
| `529` | 上游过载 | 模型服务商繁忙 |

## 401 认证失败

未携带任何密钥时，OpenAI 与 Anthropic 格式统一返回：

```json
{
  "code": "API_KEY_REQUIRED",
  "message": "API key is required in Authorization header (Bearer scheme), x-api-key header, or x-goog-api-key header"
}
```

Gemini 格式返回 Google 风格的结构：

```json
{
  "error": {
    "code": 401,
    "message": "API key is required",
    "status": "UNAUTHENTICATED"
  }
}
```

控制台自身的接口（`/api/v1/*`）未登录时返回：

```json
{
  "code": "UNAUTHORIZED",
  "message": "Authorization header is required"
}
```

### 常见原因

| 原因 | 处理 |
| --- | --- |
| 请求头里没有 Key | 检查客户端是否读取到了配置 |
| Key 拼写错误 | 检查是否混入空格、换行或引号 |
| Key 被禁用 | 在密钥页面查看状态并重新启用 |
| Key 已过期 | 新建 Key 并更新客户端 |
| 账号被停用 | 联系支持 |
| 客户端仍用旧配置 | 完全退出客户端后重启 |

密钥在控制台里的状态包括：启用、停用、被禁用、被团队管理员禁用、额度耗尽、已过期。状态不是「启用」时，请求都会被拒绝。

## 403 被拒绝

403 表示身份没问题，但这次请求不被允许。按 `message` 判断属于哪一类：

| 类别 | 典型原因 | 处理 |
| --- | --- | --- |
| 余额 | 账户余额不足以支付本次请求 | 充值或使用兑换码 |
| 分组 | 分组已删除、已停用，或当前账户不再可用 | 更换分组并重建 Key |
| 模型 | 请求的模型不在 Key 绑定的分组内 | 从该分组的模型清单里选择 |
| 协议 | 分组不接受客户端发来的接口格式 | 换客户端或换分组 |
| 客户端限制 | 例如 `claude_max` 分组只允许 Claude Code | 改用 Claude Code，或换用 `claude_kiro` |
| IP 限制 | 当前出口 IP 不在白名单内，或命中黑名单 | 调整 Key 的 IP 限制 |
| 内容风控 | 请求命中内容审核规则 | 调整输入内容后重试 |

## 429 额度或限流

| 类型 | 典型原因 | 处理 |
| --- | --- | --- |
| Key 额度 | 总限额、5 小时限额、日限额、7 天限额用尽 | 等待窗口重置，或调整 Key 限额 |
| 团队额度 | 成员的日 / 周 / 月限额用尽 | 由团队所有者调整限额 |
| 频率 | Key 的 RPM 或并发限制 | 降低请求频率或并发数 |
| 用户级 | 账户级 RPM 或并发限制 | 同上 |
| 上游 | 模型服务商限流 | 稍后重试或更换模型 |

响应带 `Retry-After` 时按其指示等待，否则指数退避。失败重试可能继续产生费用。

## 400 请求格式错误

| 情况 | 处理 |
| --- | --- |
| 未传模型 ID | 在客户端里选择模型，或在请求体里补 `model` |
| 请求体不是合法 JSON | 检查序列化逻辑和引号转义 |
| 复合 Key 的模型没带前缀 | 改成 `前缀/模型ID` |
| Key 写在查询参数里 | 改用请求头，见 [API 端点](/endpoints#认证) |
| 端点路径写错 | 去掉手动拼接的 `/chat/completions` 等后缀 |

## 5xx 服务端错误

| 状态码 | 含义 | 处理 |
| --- | --- | --- |
| `502` | 上游返回异常或连接中断 | 等待后重试，或更换分组 |
| `503` | 上游过载、暂时无可用上游 | 稍后重试，或更换模型 / 分组 |
| `529` | 上游繁忙 | 更换模型通常恢复更快 |

5xx 与客户端配置无关。持续不恢复时按[排障](/troubleshooting#怎么反馈)里的模板反馈，附上时间、模型 ID、分组和完整报错。
