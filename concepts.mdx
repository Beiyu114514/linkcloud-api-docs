本节解释文档里反复出现的术语，以及一次请求在 LinkCloud 内部经过的环节。

## 术语

| 术语 | 含义 |
| --- | --- |
| 余额 | 账户可用金额，单位 USD（`$`）。所有分组都从余额扣费 |
| 分组 | 一组模型的集合，决定可用模型、计费倍率、支持的协议和客户端限制 |
| 分组倍率 | 作用于模型单价的系数。实际扣费按模型单价和分组倍率计算 |
| 协议 | 请求使用的接口格式，例如 OpenAI Chat Completions、Anthropic Messages |
| 端点 | 客户端里填写的 API 地址（Base URL），见 [API 端点](/endpoints) |
| API Key | 调用凭据，创建时绑定一个分组，并带独立的限额、限速和有效期 |
| 复合 Key | 一个 Key 绑定多个分组，请求时用 `前缀/模型ID` 指定分组 |
| 兑换码 | 在[兑换页面](https://api.linkcloud.sh/redeem)兑换余额、并发或订阅权益的凭证 |

<Note>
LinkCloud 不使用「号池」「推理积分」这类叫法。分组说明里出现的「号池」只是对上游账号集合的口语描述，不在控制台里作为字段出现。
</Note>

## 分组

分组决定四件事：你能调用哪些模型、按什么倍率计费、接受哪种协议格式、以及是否有客户端限制。

创建 API Key 时必须指定一个分组。Key 创建后仍可点击密钥列表里的**分组**列更换，更换后立即生效。

下面是当前各分组的倍率与规模，用于快速选型。**价格、折扣和可用性以[模型广场](https://api.linkcloud.sh/models)实时显示为准**，完整模型清单见[模型与分组](/models)。

| 分组 | 品牌 | 分组倍率 | 模型数 | 说明 |
| --- | --- | --- | --- | --- |
| `free` | OpenAI | 0.001 | 2 | 公益免费模型 |
| `chatgpt_plus` | OpenAI | 1.5 | 9 | 支持满血 GPT6.1，在可用性上尽力而为 |
| `cn_llm_openai` | DeepSeek | 2 | 7 | 国产大模型低价渠道，不保证稳定性 |
| `claude_kiro` | Anthropic | 2 | 13 | 不保证缓存命中率；因 Kiro 存在内置提示词，输出风格与官方有区别 |
| `chatgpt_pro` | OpenAI | 3 | 9 | 优先保证可用性，不含日抛 PLUS 的官方订阅稳定渠道 |
| `gemini_openai` | Google | 3.5 | 5 | 谷歌 Antigravity、Gemini CLI 等官方逆向渠道 |
| `supergrok_openai` | xAI | 3.5 | 3 | Grok Heavy 号池，OpenAI 请求格式 |
| `glm_openai` | 智谱 | 6 | 2 | GLM 稳定三方渠道，OpenAI 请求格式 |
| `gpt_image` | OpenAI | 8 | 5 | 按张计费，价格只由生成图片的实际尺寸（1K / 2K / 4K）决定 |
| `chatgpt_pro_official` | OpenAI | 10 | 9 | ChatGPT 正价渠道，推荐企业和蒸馏业务接入 |
| `claude_max` | Anthropic | 12 | 17 | 官方订阅 MAX 号池，**仅限 Claude Code 使用** |

<Warning>
`claude_max` 分组只接受 Claude Code 官方客户端。用其他客户端调用该分组的模型会被拒绝。详见 [Claude Code 指南](/clients/claude-code#claude-max-分组)。
</Warning>

## 倍率与计费

价格按模型单价和分组倍率计算。模型广场在每个分组标题处显示**分组倍率**和相对官方 API 定价的**最高优惠**，并列出该分组的完整价目。

计费维度可能包括：

| 维度 | 说明 |
| --- | --- |
| 输入 / 输出 | 按 token 计费，价格以「每 1M tokens」展示 |
| 缓存读 / 缓存写 | 提示缓存命中与写入分别计价，写入分 5 分钟和 1 小时两种 TTL |
| 上下文区间 | 部分模型按上下文长度分档定价 |
| 图片 | 按张计费，价格由生成图片的实际尺寸决定 |
| 视频 | 按秒计费 |
| Fast / Standard | Fast（高优先级通道）单价与标准通道不同 |

账户余额按实际用量扣减。使用记录中可以同时看到**标准价**和**实际扣费**，两者之间的差额来自分组倍率等因素。核对方法见[用量与导出](/account/usage)。

## 协议与端点

协议是请求的格式，端点是你填写的地址，两者必须匹配：分组支持哪种协议，客户端就得用对应格式发请求。

| 协议格式 | 端点 | 典型路径 |
| --- | --- | --- |
| OpenAI 格式 | `https://api.linkcloud.sh/v1` | `POST /chat/completions`、`POST /responses` |
| Anthropic 格式 | `https://api.linkcloud.sh` | `POST /v1/messages` |
| Gemini 格式 | `https://api.linkcloud.sh` | `POST /v1beta/models/<模型 ID>:generateContent` |

完整地址列表（含中国优化线路与源站直连）见 [API 端点](/endpoints)，各协议支持的能力见[协议与兼容性](/protocols)。

## 一次请求经过哪些检查

请求失败时，按下面的顺序核对，能快速定位是哪一环拒绝了请求：

| 环节 | 检查内容 |
| --- | --- |
| 认证 | Key 是否存在、是否被禁用、是否过期、IP 是否在白名单内 |
| 分组 | 分组是否仍然存在且可用；复合 Key 的模型 ID 是否带了正确前缀 |
| 模型权限 | 请求的模型是否属于该分组 |
| 协议 | 分组是否接受客户端发来的接口格式；客户端限制是否匹配 |
| 限额与并发 | Key 的总限额、5 小时 / 日 / 7 天限额、并发与 RPM 是否超限；余额是否足够 |
| 风控 | 请求是否命中内容审核或风控规则 |
| 上游 | 通过以上检查后，请求才发往模型服务商；上游故障会表现为 5xx |

对应的状态码和报错原文见[错误码](/errors)。
